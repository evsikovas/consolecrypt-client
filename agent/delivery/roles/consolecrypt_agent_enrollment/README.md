# Installed enrollment role (source candidate)

Default OFF. This role supports Ubuntu 24.04 x86_64 with Ansible >=2.20, an already installed and verified Agent package at `/opt/consolecrypt-agent-install/opt/consolecrypt-agent`, root execution, OpenSSH 9.6 compatible Include semantics, and the normal default sshd configuration. It does not install packages, build an Agent, issue owner authority, start the Agent service or enroll a Node automatically.

`cc_agent_enrollment_manage=true` installs fixed root-owned adapters, validates public configuration/genesis, creates missing explicit accounts only as authorized, and prepares inactive configuration. It publishes neither SSH authorized keys nor a sudo grant nor an active SSH fragment. A subsequent manage-only run does not revoke an already activated role; disable/remove active grants through a separately reviewed administrative change.

Supply nonzero explicit service/operator UID/GID values. The service is `consolecrypt-agent` with `/usr/sbin/nologin`, no supplementary groups, no home creation and no SSH. `cc_agent_enrollment_create_service=true` is necessary to create it if absent; existing UID/GID/shell/group conflicts fail without modifying that account. The separate operator is `cc-agent-enroll` with a root-owned `/var/empty/cc-agent-enroll` home and the fixed restricted login shell. No account is unlocked. No default inventory UUID or UID 10001 is adopted.

Supply `cc_agent_enrollment_agent_id` and, for multi-host runs, the complete unique `cc_agent_identity_fleet_ids` public mapping. Each host owns a distinct Node/journal and independently approved deployment namespace/genesis. Genesis is public OOB localProfile or personalAccount trust with checkpoint zero; the role never derives it from a probe, renews expiry or replaces mismatched existing bytes. No Native/profile private key is copied to hosts. The Node key is generated locally only on explicit provisioning.

Bootstrap is separate: set `cc_agent_enrollment_node_provision` and/or `cc_agent_enrollment_store_init`, plus `cc_agent_enrollment_exclusive_bootstrap_approved`. The fixed Agent service must be inactive and the enrollment sudo/SSH grants absent. Private root data parents and service-owned 0700 children are checked; Node and SQL state are never implicitly created by startup/status. Init requires both journal and anchor paths absent. Partial/existing/corrupt state is denied, not reset. The approval is an administrative exclusivity prerequisite, not a process lock or proof no other local writer exists. Provisioning can write an existing legacy Node guard; opening an existing SQLite store can write WAL files.

Explicit `cc_agent_enrollment_activate=true` additionally requires preinstalled `sudo`, `pamtester` and OpenSSH, the custom operator shell already present in `/etc/shells`, existing effective `UsePAM yes`, and all three review flags: `cc_agent_enrollment_pam_context_reviewed`, `cc_agent_enrollment_sudo_nologin_reviewed`, `cc_agent_enrollment_default_sshd_config_reviewed`. The service nologin shell must NOT be made valid to bypass sudo runas checks. Review actual sudo `runas_check_shell`/PAM behavior on the host; unsupported policies fail closed, with no global sudo/PAM relaxation. `pamtester sshd cc-agent-enroll acct_mgmt` is only an account diagnostic, not proof of SSH key authentication, PAM session, RHOST/TTY policy or current daemon configuration. Context-dependent policies require manual review and refusal until resolved.

Supported SSH layout: exactly one literal GLOBAL `Include /etc/ssh/sshd_config.d/*.conf` before any Match in the main file; no nested Includes in snippets; our managed filename must sort FIRST. Other layouts require explicit administrator review, not rewriting. The validator snapshots all physical root-controlled snippets into a private full candidate and runs `sshd -t -f` and `sshd -T -f -C` without option overrides. OpenSSH restores containing Match state after an included file; `Match all` itself does not restore GLOBAL. Full effective operator/service predicates, exact subsystem and visudo are checked before keys/sudo/live publication, and actual full configuration is checked before the opt-in reload. No global sshd file is overwritten. Earlier main/global or external daemon `-f`/SSHD_OPTS configuration is not silently ignored: supported default configuration must be independently confirmed. Loopback `-C` checks are not exhaustive tests of arbitrary address policies.

The custom shell accepts only `-c consolecrypt-agent-enrollment`, ignores no original command by evaluation, and execs a fixed zero-argument sudo bridge. The sudo rule has an explicit `""` no-arguments suffix, fixed service Runas, NOPASSWD/NOSETENV, scoped non-PTY/non-I/O-logging settings, and no ALL/NOEXEC/general command. ForceCommand confines shell/exec/subsystem invocations to the same role; it does not prove the client requested the subsystem. Native must request `consolecrypt-agent-enroll-v1` with no PTY and verify the original pinned SSH session.

`enrollment-admin --status` uses one literal status request then EOF, requires one bounded successful reply, and owns a ten-second child/output deadline. It reports replay/integrity only: revision may advance, current owner/certificate/expiry are not returned, and no trust or SSH ACK is inferred. Admin helpers are root-only and absent from sudoers. Enrollment worker/signatures and Actor CAS remain authoritative.

Source-only validation is distinct from installation and actual authentication. Future acceptance must exercise the maintained role in an owned Ubuntu host, full effective SSH/sudo policy and original-session Native enrollment; no such execution is claimed by this source candidate.

Security followup (source only): child leaders remain unreaped through exact session/group cleanup; unknown descendant cleanup denies. All fixed root-file readers validate the held regular/root/nonwrite/single-link file and complete path/FD identity before data, repeat trusted ancestry afterward, and require the exact initial byte size. Effective SSH must have PermitUserEnvironment=no, no SetEnv entries, and AcceptEnv empty or containing only the closed LANG/LC_* locale names. Broader host environment rules are refused rather than globally rewritten. Failed activation may leave partial fixed publication; no ambiguous fixed file is unlinked automatically and no successful rollback or reload is claimed. Reconcile partial state through explicit administration before another activation.

Effective sudo support is deliberately closed to the Ubuntu sudo 1.9.15p5 long-listing profile with builtin sudoers plugins and files-only policy. The root helper checks all listed operator privileges, exact source/Runas/zero-argument worker and explicit NOSETENV/NOPASSWD/NOLOG_INPUT/NOLOG_OUTPUT tags. Only the documented harmless default set is accepted; unknown plugins/NSS sources, per-command/Runas defaults, extra grants/commands or unsafe environment/I/O/PTY defaults deny. Candidate syntax alone is insufficient. The exact sudo file is published and its actual effective listing validated BEFORE any SSH authorized keys or ingress snippet is published. Existing partial role publication is refused; no automatic repair or deletion occurs. This is a source-supported profile, not an assertion that any host has passed it.

Long-listing schema reference: official sudo-project SUDO_1_9_15p5 plugins/sudoers/display.c, https://github.com/sudo-project/sudo/blob/SUDO_1_9_15p5/plugins/sudoers/display.c (display_cmndspec_long/display_privs). The role does not execute any listed worker command during this policy query.

Approved identity ranges: explicit service UID/GID are 1..2147483647, allowing existing system-account IDs; operator UID/GID remain 1000..2147483647. Both pairs must be fixed, distinct and collision-checked. No caller supplies them through SSH. OOB genesis accepts the existing wire localProfile/personalAccount tenant shapes with exact context keys and canonical nonzero UUIDs, and rejects Team. It never adopts probe metadata, renews expiry or introduces authority.

Policy-query side effects: fixed sudo --version/-n -ll -U and SSH/PAM/visudo diagnostics do not execute a listed worker command or carry invitation/proof payloads. Standard host diagnostics may create ordinary audit/cache records; zero-host-write behavior is not claimed. Input is DEVNULL, environment is LANG-only, output/deadlines are bounded, and the fixed root-owned helper is the sole caller. Unknown plugin/NSS/listing/default profiles deny before keys or ingress publication.


The optional outbound/TUN role additionally invokes this validator's fixed root-only
`--tunnel-runtime-check`. It accepts no path, hash or policy arguments: the selected
verified release supplies the closed system Python3.11/3.12 pin and the actual Host
file must match it. It neither creates a runtime pin nor changes ordinary
Telemetry/Metrics enrollment requirements. Newly explicitly created service accounts
use `/var/lib/consolecrypt-agent` as their noninteractive home; existing accounts
are checked without automatic home/identity repair.
