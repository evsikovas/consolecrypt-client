# Operator enrollment deployment

Use `delivery/enrollment-node.yml` with the default-off `consolecrypt_agent_enrollment` role. Read its README before enabling any switch. The verified Agent package/current release and independent public owner genesis are prerequisites; enrollment SSH is a separate operator role, not the service account shell.

1. Review per-host public Agent IDs/deployment namespaces, exact operator SSH public keys, explicit noncolliding service/operator UID/GIDs and OOB genesis. Multi-host inventory needs complete unique `cc_agent_identity_fleet_ids` coverage. Never distribute Node/profile private keys.
2. Enable manage only. If the service account is absent, separately approve `create_service` with explicit IDs. Register the fixed restricted operator shell through the host's approved `/etc/shells` process if required; do not change PAM or make the service nologin shell valid.
3. With the Agent stopped, SSH ingress absent and exclusive bootstrap explicitly approved, provision the local Node and initialize only absent SQLite/anchor paths. Repeat initialization is intentionally denied. Review the local integrity/status output without treating it as enrollment authority.
4. Independently confirm default sshd config, PAM/account/context policy, and sudo service-nologin compatibility. Preinstall pamtester through the normal host process. Set the three review flags and activation switch. Candidate syntax/effective policy checks precede key/sudo/SSH publication and the optional reload.
5. Actual owner/device approval uses Native's original pinned SSH session and fixed `consolecrypt-agent-enroll-v1` subsystem without PTY. The SSH operator can invoke only the existing enrollment worker; it cannot choose Node paths, supply clocks, issue owner signatures, initialize/reset trust, or call the root admin helper.

Installed config/genesis are create-once exact bytes. Mismatch, corrupt/partial state, unknown reply or lost commit ACK is a denial/unknown outcome, never a reason to reset or automatically retry. Trust refresh and operator removal require separate reviewed administration. This source handoff does not claim actual install, PAM session, public-key SSH login, service activation or product enrollment acceptance.

If activation validation fails, stop and reconcile the retained fixed files manually. The role does not unlink ambiguous public SSH/sudo paths and does not claim rollback; no reload is requested on that failure path. Effective SSH environment admission must remain closed (locale-only AcceptEnv, no SetEnv and PermitUserEnvironment=no) before the restricted Python shell starts.

Supported explicit identity ranges are service UID/GID >0 and operator UID/GID >=1000, each below 2^31 and subject to distinct/collision checks. Existing-wire OOB localProfile and personalAccount genesis are supported; Team, trust adoption and expiry renewal are not. The current sudo query profile is 1.9.15p5/files-only/builtin plugins; other versions or policies require review rather than an automatic fallback. Queries may cause ordinary host diagnostics/audit/cache activity, but no enrollment payload or listed command is executed during policy validation.
