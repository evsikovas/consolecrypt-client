# Настройка локального Runner

В «Автоматизация → Окружения Runner → Добавить окружение» сначала выбирается
WSL-дистрибутив или локальный Linux. Кнопка «Найти окружение» выполняет только
диагностику. Она не загружает зависимости и не запускает плейбуки.

Мастер определяет пользователя, Python, необходимые системные инструменты и
ранее созданные ConsoleCrypt окружения. Если пользователь по умолчанию — root,
предлагается выбрать обычного Linux-пользователя и повторить поиск. Поиск не
создаёт каталогов. Произвольные окружения в других каталогах подключаются
через «Дополнительно: подключить вручную».

### Если WSL ещё не подготовлен

Рядом со списком дистрибутивов есть «Подготовить WSL». Инструкция разделяет
проверку установленных дистрибутивов, установку Ubuntu 24.04 при необходимости,
первый запуск Linux с созданием обычного пользователя и возврат к диагностике
Runner. Команды копируются только по явной кнопке. Установочную команду нужно
самостоятельно выполнить в PowerShell администратора; инструкция сама не меняет
компоненты Windows и не перезагружает компьютер. После установки нажмите
«Обновить список» и явно выберите дистрибутив. Ошибка поиска не считается
доказательством отсутствия WSL. Подробности установки и возможной перезагрузки:
[документация Microsoft](https://learn.microsoft.com/en-us/windows/wsl/install).

## Установка

Для автоматической установки сейчас поддерживаются Linux x86_64 с Python 3.12
или 3.14 и Windows с таким окружением внутри WSL2. Используются отдельные
проверенные lock-файлы для каждого Python. Нужны venv/ensurepip, bubblewrap,
git, SSH client и работоспособные user/PID/network namespaces. Само наличие
bubblewrap не считается подтверждением работоспособной изоляции.

На Ubuntu/Debian мастер предлагает команду установки недостающих системных
пакетов. «Выполнить в окружении» открывает отдельную вкладку встроенного
терминала с этой командой в выбранном дистрибутиве под выбранным обычным
пользователем. Перед открытием повторно проверяются окружение и точный состав
пакетов. Пароль sudo вводится непосредственно в терминале. Ввод этой вкладки
не попадает в историю команд для ИИ. Копирование команды также доступно.
После установки повторите поиск окружения в мастере. Без нажатия кнопки
системная установка не запускается. ConsoleCrypt не меняет Windows features,
default-дистрибутив или правила AppArmor/Firewall.
Если отсутствует сам Python, нужно сначала установить Python 3 выбранного
дистрибутива. macOS и Linux arm64 пока не имеют проверенного установочного
lock-набора; для них остаётся подготовленный удалённый Linux Runner.

Проверенный вариант использует Python дистрибутива под `/usr`. Произвольная
установка Python под `/usr/local` может пройти проверку пакетов и не пройти
sandbox: всё дерево `/usr/local` намеренно не открывается проекту. В таком
случае установка не публикуется как готовый Runner; используйте поддерживаемое
окружение. Наличие правильных версий пакетов не заменяет проверку изоляции.

«Установить Runner» — отдельное действие с предварительным описанием:

- место установки в домашнем каталоге выбранного Linux-пользователя;
- версии основных компонентов;
- необходимость загрузки зависимостей из PyPI;
- последующая проверка версий, файлов и изоляции.

Создаётся новый каталог с уникальным ID внутри
`~/.local/share/consolecrypt/runner-environments/`. Существующие окружения не
заменяются. Python venv, исходники helper и рабочее состояние принадлежат этому
каталогу. Установка выполняется без root; системный Python не модифицируется.
Символические ссылки и чужие либо доступные на запись другим пользователям
родительские каталоги отклоняются. В WSL домашний каталог под `/mnt/` не подходит.

Пакеты загружаются с `--only-binary=:all:` и `--require-hashes` из закреплённого
набора, встроенного в приложение. Настройки pip и сторонние package indexes
не наследуются: `PIP_CONFIG_FILE=/dev/null` отключает конфигурационные файлы,
а `--isolated` — пользовательские настройки и переменные pip
([конфигурация pip](https://pip.pypa.io/en/stable/topics/configuration/)).
Несовпадение SHA-256 завершает установку ошибкой. На успешный
результат также влияют точный состав пакетов и фактическая проверка sandbox.
Неуспешный каталог не получает `installation.json` и не предлагается как готовый
Runner. Он остаётся для диагностики; повторная установка создаёт новый каталог.

После успешной проверки пути заполняются автоматически. «Сохранить» отдельно
добавляет подключение в текущий профиль. Следующий поиск обнаруживает установку,
даже если профиль подключения ещё не был сохранён. Перед исполнением проекта
применяются обычные диагностика, preflight и отдельное подтверждение задания.

## Отмена и границы профиля

Поиск/установка имеют собственный случайный ID. Кнопка отмены и закрытие мастера
отменяют только соответствующую операцию. Отмена, пришедшая раньше запуска,
сохраняется кратковременно и предотвращает поздний запуск. Нельзя отменить
другую установку устаревшим ID. При блокировке или смене профиля результат не
может заполнить новый интерфейс либо сохранить подключение в другом профиле.

Установщик работает в отдельной Linux process group. Закрытие управляющего
stdin останавливает эту группу вместе с pip. Не используются `wsl --shutdown`,
остановка дистрибутива, завершение чужих терминалов или общих служб. Сырые
выводы pip и переменные окружения не передаются в интерфейс или журнал задания.
Встроенный установщик не получает SSH credentials, проекты или resolver vault.

Это интерактивное окружение, а не постоянный сервис Runner. Настройка не
включает автоматическое выполнение, расписания или сервисное делегирование.

## Редактирование подключения

Кнопка со значком карандаша в карточке Runner открывает текущие имя, тип,
WSL distribution/user либо SSH-хост и пути. Сохранение сначала отключает
неактивное соединение. Активное задание, inventory preview, импорт или scope
должны завершиться: они не отменяются редактированием. Затем native обновляет
запись с прежним ID и проверяет исходную revision одной транзакцией. Устаревшая
форма не перезаписывает новые настройки. Неизвестная версия остаётся read-only.
После изменения подключите Runner заново через «Проверить окружение».


## Удалённая настройка и проверка готовности (R6 preview)

Для удалённого Linux окружения выберите сохранённый SSH-хост и нажмите
«Найти окружение». Используется отдельное соединение с обычной проверкой
host key и сохранённой цепочкой jump-хостов. Сканирование не запускает проект.
Автонастройке нужен non-root SSH-пользователь; переключение root через sudo
и создание учётной записи не выполняются автоматически.

Поддерживаются Python 3.12 и 3.14 на Linux x64. Если найдено готовое
управляемое окружение, выберите его и сохраните подключение: повторная
установка не требуется. При необходимости установка создаёт новый каталог,
проверяет закреплённые пакеты, настоящий импорт helper и sandbox и только
после этого отмечает его готовым. Домашний каталог с noexec отклоняется:
установщик не меняет параметры монтирования.

Для недостающих системных пакетов показывается точная команда. Кнопка
«Выполнить в окружении» повторно проверяет план на выбранном узле и открывает
отдельный SSH-терминал. Пароль sudo вводится там. Командный трекер этого
терминала отключён, чтобы ввод пароля не попадал в last-command/ИИ-контекст.
После ручной установки повторите поиск; команда не считается успешной заранее.

Сканирование/автоустановка используют отдельный закрываемый SSH-сеанс.
Отмена или потеря управляющего канала завершает только их собственную группу
процессов. Это не завершает другие терминалы или работающий прежний Runner.
Открытый пользователем терминал установки системных пакетов имеет обычный
интерактивный жизненный цикл терминала.


## Обновление управляемого Runner

Поиск сравнивает отпечаток встроенного пакета с квитанциями управляемых
установок. Для выбранного устаревшего окружения появляется отдельное
«Обновить Runner». Подтверждение создаёт новый каталог с закреплёнными
пакетами и проверяет его; прежний Runner и его состояние сохраняются.
Сохранение подключения на новый путь выполняется отдельно. Актуальному
окружению повторная установка не предлагается.

Новая проверка `target_match_v1` обязательна перед подтверждением задания:
выбранный playbook должен соответствовать хотя бы одной явно утверждённой
цели. Старый Helper без этой возможности требует обновления; клиент не
пропускает проверку ради совместимости. Для окружения, подключённого вручную,
обновите доверенный пакет helper в выбранном Linux/WSL и подключитесь заново.

SSH-логин может быть псевдонимом системной учётной записи. Подготовка
терминала сравнивает фактическое имя по UID в двух сканированиях, а не
SSH principal с `pwd`-именем; пользователь, набор пакетов, non-root состояние
и проверяемый SSH-маршрут всё равно должны оставаться согласованными.


## Очистка прежних управляемых окружений

После обновления старые каталоги остаются намеренно: сохранённая запись Runner
или другой профиль ещё могут использовать прежний Python, Helper и состояние.
Удаление записи подключения само по себе не удаляет файлы на выбранном узле.

Новая очистка использует отдельный поиск управляемых каталогов выбранного
Linux/WSL/SSH-пользователя. Сканирование не удаляет файлы. Вручную подготовленные
окружения и произвольные пути не принимаются как кандидаты. Нужны непривилегированный
владелец, проверяемая квитанция установки и поддерживаемая защита файловой системы;
при отсутствии такой проверки удаление недоступно. Native Windows/macOS очистка
в этой версии не поддерживается; это не ограничивает обычную работу Runner.

Перед удалением приложение показывает точный каталог, количество записей и байт,
а также предупреждение: удаляются Python, Helper, состояние и рабочие данные
внутри этого каталога. Счётчики не означают объём освобождённого места на диске.
Текущий выбранный Python, ссылки сохранённых Runner, соединения и незавершённые
задания текущего профиля блокируют очистку. Другие закрытые профили не проверяются:
приложение прямо сообщает об этом перед подтверждением. Не удаляйте окружение,
которое ещё нужно такому профилю.

План действует не более 60 секунд и используется один раз. Изменение выбора,
узла, профиля, ссылок или содержимого каталога требует нового поиска и проверки.
Native повторно проверяет каталог перед изменением; ссылки и точки монтирования
внутри границы удаления не обходятся. Сначала каталог перемещается в карантин
внутри проверенного родителя, затем удаляются его проверенные записи. Отмена,
блокировка или разрыв управляющего канала прекращают последующие шаги удаления;
уже удалённые файлы не восстанавливаются. Частично удалённый карантин можно
проверить заново и явно подтвердить новый план. Автоматического повтора нет.

Общая очистка входит в локальные R9/R10. В исходниках следующего preview
корзина также доступна рядом с каждым найденным окружением. Она выполняет новый
поиск и открывает проверку именно выбранного каталога; удаление требует
отдельного подтверждения. После попытки удаления список читается заново.

Чтобы удалить выбранное, но не используемое окружение, сначала нажмите
«Снять выбор окружения» или снимите его флажок. Это очищает поля текущей формы,
но не изменяет сохранённые подключения. Если окружение связано с сохранённым
Runner, сначала измените или удалите эту запись подключения. При обновлении
списка приложение не выбирает другое окружение автоматически.

«Сохранить», «Назад» и «Закрыть» находятся в общей нижней строке действий;
сохранение по-прежнему проверяет поля и версию редактируемой записи.
Во время разработки удаление проверяется только на собственных временных
стендах, пользовательские каталоги не очищаются.

## Подключение постоянной службы Runner

Это отдельный режим разрабатываемой версии. Служба работает на выделенном
Linux-узле и не зависит от открытого окна ConsoleCrypt. Обычные подключения
WSL/SSH продолжают выполнять интерактивные задания; смена их названия или пути
не превращает их в постоянную службу.

В «Окружениях Runner» выберите режим службы, сохранённый SSH-хост и идентификатор
уже установленного экземпляра службы. Идентификатор выдаёт установка;
произвольная команда, URL или путь к Python здесь не вводятся. Сохранение
запоминает подключение, но не устанавливает компоненты и не выдаёт разрешений.
Отдельный канал использует проверку SSH host key; неподдерживаемый маршрут
отклоняется до обращения к службе.

Для расписания выберите проект, playbook и конкретные цели, затем действие
«Делегировать расписание». Укажите часовой пояс, дни, время и лимиты. Перед
подтверждением приложение показывает проверенный снимок проекта, цели,
полномочия и отпечатки ключей службы. Подтверждение действует не более минуты;
изменение проекта, подключения или профиля требует новой проверки. Начальное
делегирование ограничено 24 часами и не продлевается автоматически.

Служба получает отдельное ограниченное разрешение и зашифрованные данные для
выбранного задания. Она не получает пароль от пользовательского хранилища или
произвольный доступ ко всем сохранённым SSH-хостам. Для production-проектов
фоновое делегирование пока запрещено; интерактивное дополнительное подтверждение
паролем владельца относится к другому режиму.

«Статус» читает состояние по явному действию. «Отозвать» сначала сохраняет
локальный запрет, затем пытается доставить подписанный отзыв. Если узел
недоступен, результат доставки остаётся неизвестным: приложение не сообщает
об успешном удалённом отзыве заранее. Ранее скопированные на целевой узел
секреты требуют отдельной ротации.

Закрытие предварительного просмотра отменяет только ещё не подтверждённую
настройку. Отключение клиентского SSH-сеанса не останавливает уже разрешённую
службу. Удаление записи подключения также не удаляет установленную службу и
её данные; для этого нужен отдельный проверяемый план удаления на узле.

Полная приёмка установки, перезапуска и выполнения через публичный интерфейс
ещё выполняется. Компонентные проверки транспорта и ключей не заменяют её.

### Сохранённые результаты службы: текущий исходный код

В карточке делегирования предусмотрено отдельное действие «Прочитать
сохранённые результаты службы». Оно запрашивает только завершённые задания
выбранной сохранённой службы и не запускает Node, задание или повтор выполнения.
Чтение привязано к исходному профилю, unlock nonce и версии подключения.
Открытие карточки, разворачивание строки и ожидание не вызывают фоновый опрос.

Строка показывает исходный Job ID, известный итог Runner, результат на цели,
время UTC, exit code и отдельно записанные признаки отмены и timeout. Отсутствие
признака отображается как «Неизвестно». Неизвестный результат на цели или
частичные изменения остаются Unknown, даже если процесс Runner завершился.
Exit code сам по себе не подтверждает успех всех задач. Пустой успешно прочитанный
список означает отсутствие подходящих завершённых записей, а не успешное задание.
Сырые события, вывод команд, facts, переменные и секреты в эту карточку не входят.

Если чтение недоступно или исходный контекст изменился, новые результаты не
публикуются; автоматического повтора нет. Статус разрешения, факт локального
запрета и доставка отзыва остаются отдельными сведениями: ни один из них не
заменяет сохранённый результат задания и не гарантирует отсутствие удалённых
изменений.

На этом срезе исходников optional UI и Native read-path уже добавлены, а новый
результатный метод ещё не подключён через актуально сгенерированный production
Dart adapter. Поэтому кнопка остаётся скрытой у сервиса без этой capability.
Проверки UI с управляемым портом не заменяют приёмку реального публичного чтения
после выхода Node. Это описание не относится к уже опубликованному установщику.
