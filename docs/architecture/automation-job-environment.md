# Версии окружения в истории Ansible

Интерактивный Runner сохраняет вместе с принятым заданием ограниченную копию
идентичности окружения: версию helper и протокола, Python, ОС и архитектуру,
версии инструментов и установленных библиотек, digest исходников helper,
lock-файла и файлов зависимостей. Запись находится в `environment` состояния
задания и возвращается обычным `job_get`; клиент сохраняет её в своей истории
вместе с результатом Runner. В истории есть отдельный блок версий запуска.
Схема receipt должна поддерживаться, а его digest совпадать с manifest:
иначе интерфейс сообщает, что связанных сведений нет, и не подставляет
текущие версии. Полный JSON остаётся в сворачиваемых технических сведениях.

Это сведения именно на момент приёма. Повторное чтение после обновления
инструментов не подменяет их свежим probe. Изменение окружения между приёмом
и фактическим исполнением по-прежнему блокирует запуск; новый receipt сам по
себе не разрешает исполнение и не меняет подписанный manifest.

Перед устойчивым приёмом Runner пересчитывает SHA-256 канонической JSON
идентичности и сравнивает его с `environment_digest` подписанного manifest.
Несовпадение или превышение 64 КиБ отклоняет приём до создания job/nonce.
Версии сохраняются в той же атомарной записи, что и подтверждение приёма;
повтор job ID с тем же manifest возвращает прежнюю запись. Перезапуск не
означает новое выполнение.

Произвольные поля probe не копируются: используется закрытый список полей
идентичности. Переменные процесса, домашний каталог, credentials, параметры
playbook и содержимое проекта не являются частью receipt. Сохранённые
сведения не следует считать удалённой аппаратной аттестацией: Runner уже
находится в принятой пользователем границе доверия.

Старые записи без `environment` остаются читаемыми. Их точные версии задним
числом не восстанавливаются по сегодняшнему probe. Формат транспортного
manifest v1 не изменён. Сводка по хостам использует только alias из
утверждённого manifest, показывает 25 целей на странице и отличает отсутствие
счётчика от нуля. Отрицательные, дробные и чрезмерные счётчики не становятся
успешным нулём. Технический предпросмотр ограничен 16 384 символами и строится
только при раскрытии; полный журнал читается отдельно по cursor.

В журнале задания появился блок «Итоги задач». Он показывает только результаты
на выбранной странице: задачу, утверждённый хост, статус, изменения, exit code
и доступную ошибку. Строки не объединяются по совпадающему названию задачи.
Для `no_log`/`censored` чувствительный результат скрыт, отсутствующий счётчик
остаётся неизвестным.

Чтение идёт по существующему cursor, по 50 событий. Есть следующая/предыдущая
страница, обновление и возврат к началу; фильтр действует на текущую страницу.
Переключение разделов и чтение журнала не создают новое выполнение. Полная
платформенная приёмка остаётся отдельным этапом G1.
