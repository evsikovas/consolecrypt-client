# Создание проекта и выбор inventory

## Файлы и роли

«Открыть папку» сначала открывает системный выбор каталога. Проект получает
имя выбранной папки; «Переименовать» меняет отображаемое имя отдельно, не
переименовывая каталог на диске. Отмена выбора не создаёт проект.

В меню создания доступны «Новый плейбук», «Создать роль» и «Другой файл».
Новый плейбук открывается черновиком YAML; сохранение и запуск остаются
отдельными действиями. Если playbook.yml уже есть, предлагается свободное имя.

Создание роли записывает стандартные каталоги defaults, files, handlers,
meta, tasks, templates, tests и vars в roles/<имя>. Имя — строчные латинские
буквы, цифры и подчёркивание, первая буква обязательна. Готовится отдельный
временный каталог и публикуется целиком с запретом замены существующего пути.
Даже существующая пустая папка не перезаписывается. Ошибка оставляет старую
роль без изменений; удаляется только временный каталог этой операции.

Шаблон содержит безопасную демонстрационную debug-задачу и пустые переменные,
handlers и dependencies. Лицензия и автор не назначаются приложением.
Роль надо явно добавить в playbook; создание роли ничего не исполняет и не
загружает из Galaxy. Установка внешних зависимостей — отдельная возможность.

## Зашифрованный экспорт и импорт проекта

На Windows проверен полный сценарий через интерфейс Dart/Rust: экспорт,
предпросмотр, отдельное подтверждение, создание проекта, редактирование и
повторное открытие после разблокировки. Отмена просмотра не создаёт проект.

«Экспорт зашифрованного пакета» сохраняет выбранные файлы в `.ccproject`.
Просмотрите состав и задайте **отдельный пароль пакета**: это не пароль профиля
ConsoleCrypt и не пароль Ansible Vault. Существующий файл не перезаписывается.
Из пакета не восстанавливаются credentials, привязки к хостам, inventory и
Runner. Известные служебные файлы, ключи и файлы паролей исключаются; однако
произвольный YAML/INI может содержать введённые пользователем секреты.
Проверьте выбранные файлы перед передачей пакета другому человеку.

В «Импорте нового проекта» выберите пакет, введите его пароль и имя проекта,
затем нажмите «Проверить пакет». Просмотр состава ещё не создаёт проект.
Только отдельное действие «Импортировать» создаёт новый управляемый проект
с новым ID; существующий проект или каталог не заменяется. Изменение имени,
файла или пароля требует новой проверки. Отмена или блокировка профиля
прекращает неподтверждённый просмотр. После создания отдельно настройте
inventory, Runner и цели, выполните проверки и подтвердите запуск:
импорт сам ничего не исполняет и не устанавливает зависимости.

Создание проекта из пакета ограничено поддержанными локальными файловыми
системами: NTFS в Windows и проверяемыми локальными файловыми системами Linux.
Каталог профиля должен пройти проверку прав и безопасности; приложение не
исправляет права существующего каталога автоматически. Импорт на macOS и
работа через Android SAF / iOS security-scoped URL пока не поддержаны.
Сетевые расположения и неподдерживаемые пути отклоняются. Если после
подтверждения требуется восстановление, повторный импорт не запускается
автоматически: это не сообщение о гарантированном откате.

## Источники inventory

Диалог предлагает сохранённые хосты ConsoleCrypt, файлы проекта или оба
источника. Выбор папки добавляет снимок ID текущих SSH-хостов, включая вложенные
папки. Новые хосты, добавленные в папку позднее, автоматически в проект не
попадают. Папки приложения не превращаются в имена групп Ansible: группы
inventory настраиваются отдельно и сохраняются при смене источников.

Выбор сохранённых хостов не требует Runner для чтения файлов. Для внешнего
inventory сохраняются предпросмотр и явная привязка записей к Host ID.
При смешанном источнике доступны выбранные сохранённые ID и внешние привязки;
при «только файлы» — только внешние привязки. Для каждого запуска выбирается
подмножество допустимых целей. Native проверка отклоняет лишний ID до
подключения и обращения к целевым credentials.

Версия 2 ProjectInventory хранит selected_hosts. Старые документы версии 1
сохраняют прежнюю семантику до явного выбора источника. Список может быть
пустым: это отсутствие разрешённых сохранённых целей. Источники, снимок ID
и revision проекта обновляются одной транзакцией SQLCipher. Устаревшая revision
отклоняется без частичного сохранения; неизвестная версия остаётся read-only.

## SSH и туннели

Удалённый Runner выбирается из сохранённых SSH-хостов и использует их
jump-chain с проверкой ключей каждого узла. Целевые SSH-подключения начинаются
из Runner через direct-tcpip; для WSL — из явно выбранного distribution/user.
Проверки host key и аутентификация остаются в Rust, проект не получает ключи.
Маршрут и origin связаны с подтверждением задания; изменение требует новой
проверки. SSH-маршрут показывается в карточке подтверждения.

Это не автоматическое использование любого ранее открытого port-forward:
127.0.0.1 относится к ОС, где начинается соединение. Windows listener нельзя
считать доступным из WSL или удалённого Runner без проверки. Сохранённые
terminal forwards и agent forwarding не включаются при запуске Ansible.
Неподдерживаемый proxy/backend отклоняется без смены маршрута.

## Предложения ИИ

Предпросмотр показывает выбранный текст после фильтрации до обращения к
модели. Генерация включает JSON object/schema только если выбранный provider
объявляет соответствующую возможность; без неё остаётся текстовый JSON-контракт.
Проверка схемы, точного пути, зависимостей и полномочий остаётся в native коде.
JSON-режим не подтверждает семантику Ansible и не даёт права исполнения.

Для встроенной модели с контекстом 4096 установлен бюджет ответа 2048 токенов.
Большой исходный файл всё равно может не поместиться в контекст: сократите
выбранный фрагмент или используйте подходящую модель. Установка лимита не
обещает, что маленькая модель выполнит любое задание или сгенерирует роль.

Ошибки неполного/некорректного предложения, отсутствующей модели и HTTP-ошибки
провайдера показываются отдельно. Ответ с лишними полномочиями, другим путём
или некорректным контрактом не записывается и не запускается. В диагностику
ошибки не включаются ответ модели, provider error body или API-ключ.

Модель может ошибочно перечислить `ansible.builtin` как скачиваемую зависимость.
Два точных обозначения — `ansible.builtin` и `collection:ansible.builtin` —
нормализуются в примечание для проверки: эти модули поставляются с закреплённым
ansible-core выбранного Runner. Заявленная моделью версия встроенных модулей
не меняет окружение и не становится pin внешней загрузки. Все остальные
зависимости по-прежнему требуют допустимый источник и точную версию; wildcard,
latest, неизвестные источники и лишние поля полномочий отклоняются.


## Запрос ИИ и сравнение изменений (R6 preview)

Выбранный открытый файл можно включить в запрос или исключить флажком.
До отправки показываются задача и содержимое после native-фильтрации; полный
запрос можно раскрыть. Отправка происходит только отдельной кнопкой.

Предложение существующего плейбука показывает изменения и вкладки До/После.
«Принять изменения» помещает результат в несохранённый редактор, «Отклонить»
сохраняет прежний текст. Если во время генерации изменились проект, файл или
текст редактора, позднее предложение не заменяет текущий черновик. Запись на
диск и проверка конфликтов остаются отдельным действием «Сохранить».

## Запуск без блокирующего окна

В разделе Автоматизация параметры запуска, проверка проекта, подтверждение
и история заданий открываются внутри рабочего пространства. Можно перейти
в Терминал или другой раздел и вернуться к заданию. Принятое native-задание
не отправляется повторно при возврате. Возврат к проектам сбрасывает
неподтверждённую проверку; новое исполнение снова требует проверки и согласия.

Сообщение «Проверки не пройдены» не означает само по себе неисправность Runner:
нужно посмотреть отдельные результаты syntax/lint, код завершения и доступный
вывод. Подтверждение исполнения недоступно, пока обязательные проверки не пройдут.


## Совпадение `hosts` и выбранных целей

Выбор SSH-хостов в КК не создаёт произвольную группу из текста плейбука.
Например, `hosts: docker_hosts` требует явной группы `docker_hosts` в
inventory. Для задания со сформированным КК inventory `hosts: all` относится
только к выбранным и утверждённым целям; остальные хосты профиля не добавляются.
Если плейбук не совпал ни с одной утверждённой целью, проверка завершается
ошибкой до выполнения задач. Отдельные пустые plays допустимы, если другой
play совпал с утверждённой целью. КК не переименовывает группы автоматически.

`ansible-lint` может отклонить YAML до запуска, например из-за слишком длинной
строки. Исправьте указанную строку либо согласованную конфигурацию проекта;
клиент не отключает обязательные проверки. Режим «Проверка» передаёт check
mode в Ansible и не является обычным применением плейбука. Реальные изменения
требуют выбора «Применение», свежей проверки и отдельного подтверждения.

## Редактор и настройки проекта (R8 preview)

Редактор показывает исходные номера строк, подсвечивает YAML, директивы Ansible,
модули и выражения Jinja. Стрелка у номера строки сворачивает задачу или блок.
Сворачивание меняет только представление: скрытый текст остаётся в документе,
сохраняется на диск и участвует в проверке. Копирование выделения, охватывающего
свёрнутый блок, включает исходный текст блока, а не служебную строку сворачивания.
Редактирование ограничено 1 МиБ UTF-8; для больших документов подсветка и
сворачивание ограничиваются отдельно, чтобы не блокировать интерфейс.

Значения известных полей паролей в INI/YAML (`ansible_password`,
`ansible_ssh_pass`, `ansible_become_password` и другие поддержанные псевдонимы)
по умолчанию скрыты. Скрытое представление доступно только для чтения:
«Показать» разрешает правку и включает штатную защиту захвата экрана согласно
настройкам приложения. Через 20 секунд значения снова скрываются. Пока значения
скрыты, выделение, копирование и accessibility используют маску. Сохранение всегда
берёт исходный документ; маска не подменяет пароль на диске. Это защита отображения,
а не шифрование файла и не универсальный поиск любых секретов в произвольном тексте.

В следующем локальном preview пункт «Настройки Ansible» находится в меню «⋯»
выбранного проекта; создание файлов и шаблонов — в соседнем меню «+».
Пункт настроек открывает форму `ansible.cfg`:
сбор фактов, `any_errors_fatal` и таймаут действия задачи. Форма изменяет только
явно выбранные параметры, сохраняет остальные строки и комментарии и использует
обычную проверку SHA файла перед записью. Неоднозначный INI нужно открывать
расширенным редактором. Параметры запуска и playbook могут переопределять defaults.
Inventory, параллелизм задания и проверка SSH-ключей остаются под управлением КК;
`host_key_checking=False` не отменяет проверку ключей Native. Общего allowlist для
прочих параметров `ansible.cfg` в этой версии нет.

## Нижняя консоль и история (R8 preview)

«Вывод» содержит журнал Ansible с цветами статусов и итогом. «Техническая
информация» содержит отдельные диагностики модулей и структурированные сведения.
Прокрутка каждой вкладки и раскрытые блоки сохраняются при обновлении журнала.
Кнопка следования журналу относится к прокрутке, а не к паузе выполнения.
После завершения она исчезает; крестик закрывает панель. Журнал можно снова
открыть из раздела «Задания». Сворачивание и закрытие представления не отправляет
повторный запуск и не отменяет принятое задание. Повтор — новая проверка и
подтверждение актуального проекта, целей и окружения.

У сохранённого Runner есть явное действие обновления окружения. Оно использует
тот же идентификатор записи и проверку revision; удалять Runner и восстанавливать
привязки проекта не требуется. Установка требует отдельного действия пользователя,
а активные задания должны завершиться до изменения окружения.


## Компактная панель выполнения (следующий локальный preview)

На широком окне имя плейбука, состояние, вкладки «Вывод» / «Техническая
информация» и действия расположены в одной строке высотой 36 px. На узком
окне вкладки переходят на вторую строку (общая высота 64 px). Свёрнутая
панель занимает 36 px. Пояснение о журнале доступно в подсказке; оно не
занимает отдельную строку. Эти изменения отсутствуют в неизменяемом R8 ZIP.

### Исправление после ошибки задания

В списке заданий у неуспешного запуска можно предложить исправление с ИИ.
Открывается текущий сохранённый плейбук; несохранённые правки проходят обычный
диалог сохранения. Журнал не передаётся модели автоматически: пользователь
отдельно загружает страницу результатов и выбирает нужные строки. Скрытые
`no_log` результаты недоступны для выбора. Перед отправкой показывается полный
запрос после существующей фильтрации.

Принятие предложения оставляет черновик в редакторе. Сохранение создаёт новую
ревизию с проверкой конфликта; новый запуск требует отдельной проверки и
подтверждения. Прежние результаты остаются доступны, поскольку предыдущий
запуск мог уже изменить часть серверов. Автоматического отката или применения
предложения нет.
