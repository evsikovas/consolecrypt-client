# Обязательные параметры запуска проекта

В корне проекта можно создать обычный файл `.consolecrypt-inputs.json`.
Он задаёт, какие **параметры запуска extra_vars** пользователь обязан заполнить
для конкретного плейбука. В файл записываются только имена, без значений.
Создать и редактировать его можно через «Новый файл» в проекте либо во
внешнем редакторе.

```json
{
  "version": 1,
  "playbooks": {
    "playbook.yml": {
      "required_extra_vars": ["service_name", "listen_port"]
    },
    "maintenance/check.yml": {
      "required_extra_vars": ["expected_status"]
    }
  }
}
```

В параметрах задания для первого плейбука, например:

```json
{"service_name": "example-service", "listen_port": 8080}
```

Проверяется наличие значения, отличного от `null` и пустой строки. `false`,
`0`, списки и объекты допустимы. Значения из `host_vars`, `group_vars` или
defaults роли не заменяют явно требуемые **extra_vars**. Проверка не исполняет
Jinja и не пытается автоматически найти все переменные произвольного кода
Ansible. В отсутствие файла поведение существующих проектов сохраняется.

Проверка выполняется в изолированном syntax-check guest, до выдачи целевых
credentials. При отсутствии параметра review показывает его имя и не позволяет
подтвердить задание. Другие значения из формы в эту диагностику не выводятся.
Сам файл входит в обычный снимок проекта, его SHA-256 и Git diff; изменение
требований требует новой проверки и нового подтверждения. Формат подписанного
manifest не меняется: уже подписываются digest проекта и параметров.

Формат v1 строгий: неизвестные поля, будущая версия, дубли ключей, пути за
пределами проекта и неверные имена отклоняются. Лимиты: 32 КиБ, 128 плейбуков,
64 имени для плейбука, имя до 128 ASCII-символов в формате идентификатора.
Префиксы `ansible_` и `consolecrypt_` зарезервированы. Неподдерживаемый файл
не переписывается и не удаляется автоматически.

Имя `.consolecrypt-inputs.json` должно иметь именно такой регистр. Вариант
с заглавными буквами отклоняется, чтобы при переносе Windows→Linux требования
не исчезли как будто optional-файл отсутствует. Эта защита добавлена в source
после Windows preview r1 от 11 ноября; неизменный ZIP r1 её не содержит.

Runner должен явно сообщать capability `declared_inputs_v1`. Если в проекте
есть этот файл, старый helper не может проигнорировать требования: native-клиент
блокирует проверку до обновления выбранного Runner. Номер транспортного
протокола v1 остаётся прежним, совместимость определяется отдельной capability.

Это отдельная проверка объявленных входов. В source после preview r2 метаданные
ИИ-предложения сохраняются через отдельный просмотр diff в
`.consolecrypt-requirements.json`; этот файл проверяется вместе с ручными inputs,
не переписывая их. См. [Reviewed requirements](automation-reviewed-requirements.md).
ИИ по-прежнему создаёт несохранённый черновик; его ответ не даёт прав на запуск.
Установка зависимостей, SecretRefs и Ansible Vault требуют дальнейшей реализации.

Проверка охватывает запуск в нативном окружении и в гостевой системе.
