# Ansible Vault в проектах автоматизации

Ansible Vault и хранилище ConsoleCrypt — разные сущности. В параметрах запуска
можно явно подключить выбранные учётные данные с паролем Ansible Vault.
Существующая ссылка в проекте сама по себе не даёт согласия на выдачу пароля.
В файлах проекта сохраняется ссылка, а не пароль.

Подключение действует для выбранной ревизии проекта, Runner, credential и
подтверждённого задания. Изменение исходников или выбранной ссылки требует
новой проверки и подтверждения. Старый Runner без нужной возможности
отклоняется; обновление выполняется через существующий интерфейс Runner.

## Проверки и выполнение

Пользователь отдельно разрешает пароль для syntax/lint: эти проверки могут
загружать код проекта. Пароль передаётся через отдельный короткоживущий канал
с фиксированным назначением. В изолированную среду попадают только проверенный
исполняемый клиент и конкретный сокет; родительские каталоги и произвольные
дескрипторы не наследуются. Канал проверки не становится общим resolver для
выполнения.

После подтверждения подписанный manifest связывает отдельную выдачу материала
с точным заданием. Пароль не помещается в argv, пользовательские переменные
окружения, снимок проекта или журнал задания. ИИ не получает ни пароль,
ни подключение к этому каналу. Для задания с Vault diff выключен. Подробный
вывод проверок скрывается, чтобы ошибки расшифровки не раскрывали содержимое.

Получивший пароль процесс Ansible и исполняемый им код входят в границу доверия.
`no_log` скрывает обычные результаты чувствительных задач; это не защита от
намеренно вредоносного плейбука, который выводит или отправляет расшифрованные
значения. ConsoleCrypt не обещает автоматически распознать все такие значения.

## Блокировка и отмена

По умолчанию блокировка отменяет задание и новую выдачу материала. При явно
выключенном «Отменять при блокировке» уже подтверждённое конкретное задание
может завершиться, пока хранилище закрыто. Это не позволяет искать другие
секреты или запускать новое задание из заблокированного хранилища.

Остановка процесса может оставить частичные изменения на сервере. Поэтому
результат `unknown` сохраняется, даже если запрос отмены выполнен. Известные
признаки отмены и тайм-аута сохраняются и при ошибке последующей очистки канала;
такая ошибка не превращается в успех. Повтор — отдельное решение после
просмотра результата, автоматического отката нет.

## Проверенная граница

Реальная проверка Windows Native → отдельный SSH Runner → отдельная SSH-цель
прошла через обычные prepare/подпись/исполнение: неверный пароль отклонён,
верный работает, отмена по блокировке и явная отмена не выдали материал,
разрешённое продолжение завершилось до разблокировки. Проверены неизменность
проекта, завершение собственных процессов и отсутствие пяти временных корней
операций. Источник доказательства —
`automation-e1-next/ansible-vault-v1/job-purpose-v1/normal-job-proof-v1/evidence/normal-job-final-source.json`
в рабочем каталоге проекта. Пакет приложения после этих изменений ещё не
выпускался; общая приёмка платформ остаётся этапом G1.
