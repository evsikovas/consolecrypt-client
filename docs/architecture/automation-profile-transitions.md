# Выход и смена профиля при выполнении Ansible

Локальное задание может продолжаться при закрытии окна его результата. Оно
остаётся в общем списке, пока работают приложение и helper. Выход из приложения
или смена профиля требуют отдельного решения, если есть активные задания:

- дождаться их завершения;
- отменить задания и дождаться очистки их рабочих процессов;
- остаться в приложении без завершения задания.

Пока рассматривается выход, новые подтверждения запуска блокируются. Ожидание
не блокирует вопросы пароля и host key уже выполняющегося задания. Можно
отказаться от ожидания и вернуться к работе с текущим профилем.

При неизвестном результате команды могли частично выполниться или продолжать
работу. Пользователь отдельно подтверждает, что понимает это состояние.
Разрешение закрыть приложение не помечает такое задание успешным или отменённым
и не снимает блокировку его неизвестного результата. Если неизвестный результат
возник во время ожидания, требуется новое решение.

Проверка выхода использует текущие задания в памяти. Она не пытается открыть
запечатанную БД заблокированного профиля ради чтения истории. Восстановление
истории после перезапуска остаётся явным действием при открытии списка заданий.

## Установка обновления Windows

Перед запуском обновления сначала проверяется уже загруженный установщик,
затем получается одноразовое разрешение выхода. «Остаться» сохраняет файл в
кэше и не запускает установщик. Разрешение привязано к текущей операции и
истекает; устаревший ID не может снять другое разрешение. Закрытие приложения
после одобрения использует то же разрешение.

Установщик ждёт завершения конкретного процесса. Тайм-аут не считается
завершением. Параметр `/NOCLOSEAPPLICATIONS` исключает автоматическое закрытие
приложений установщиком. Это не обещает продолжения локальных заданий после
выхода или перезагрузки; постоянный удалённый сервис Runner — отдельный этап ТЗ.
