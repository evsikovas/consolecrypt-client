# Проверка закреплённых зависимостей проекта

Рабочая часть ANS-03/RUN-03. Установщик из ANS-05 ещё не реализован.
Эта возможность проверяет **уже размещённые в проекте** роли и collections,
не загружает архивы, не вызывает Galaxy и не меняет глобальное окружение.
Она появилась после Windows preview **r1** от 11 ноября. Неизменный ZIP r1
её не содержит; доработка предназначена для следующей сборки r2.

Optional-файл `.consolecrypt-dependencies.json` в корне проекта:

```json
{
  "version": 1,
  "dependencies": [
    {
      "kind": "role",
      "name": "example_role",
      "version": "1.2.3",
      "source": {
        "url": "https://example.test/roles/example_role-1.2.3.tar.gz",
        "sha256": "<SHA-256 исходного архива, 64 строчных hex-символа>"
      },
      "tree_digest": "<digest установленного дерева, 64 строчных hex-символа>"
    }
  ]
}
```

Роль проверяется в `roles/example_role`. Collection с `kind: collection` и
`name: example.collection` — в
`collections/ansible_collections/example/collection`. Имена и компоненты
namespace ограничены `[a-z][a-z0-9_]{0,63}`; подмена `ansible.builtin`
запрещена. Версия — непустая ASCII-метка до 80 символов, `latest` не
принимается. Байты фиксируются digest, а не поиском свежей версии по метке.

`tree_digest` использует тот же формат, что снимок проекта: SHA-256
канонического JSON `{"version":1,"entries":[...]}` для всех файлов и
каталогов внутри установленной зависимости. Пути отсчитываются от её
корня; учитываются содержимое, размер и переносимый mode каждого файла,
включая пустые каталоги. Это не SHA-256 одного YAML-файла или архива.
Для роли требуется `tasks/main.yml` либо `tasks/main.yaml`; для collection —
`galaxy.yml` либо `MANIFEST.json`.

Проверка проходит первой в syntax-check guest, без target socket, домашнего
каталога и сетевого доступа. Parent передаёт только уже проверенную metadata
точного снимка отдельным read-only файлом, до 32 МиБ; пути из lock-файла не
используются для открытия произвольных host-файлов. Проекция dependency
дерева вычисляется из этих entries. Сам lock-файл и всё дерево входят в
обычный digest проекта и diff перед подписанием задания.

Лимиты lock: 64 КиБ и 32 зависимости. Схема строгая: неизвестные поля,
будущая версия, дубли JSON-ключей/назначений, credentials/query/fragment в
URL, HTTP, отсутствующий или изменённый каталог отклоняются. Отсутствующий
lock сохраняет прежнее поведение. Пустой список ничего не устанавливает.
Имя root-файла должно иметь точно указанный нижний регистр. Вариант вроде
`.CONSOLECRYPT-DEPENDENCIES.JSON` отклоняется, а не превращается в отсутствующий
optional-файл при переносе с Windows на Linux.
Helper сообщает `locked_dependencies_v1`; native-клиент блокирует проект
с этим файлом на старом Runner, который мог бы проигнорировать проверку.

`source` пока является **заявленной provenance**, а не доказательством
происхождения файлов. Проверка установленного `tree_digest` не подтверждает,
что кто-то действительно скачал архив и сверил его `source.sha256`.
Будущий установщик должен показать сетевой источник, получить явное
подтверждение, проверить архив и безопасную распаковку, затем связать
полученные файлы с receipt. Эта проверка не заменяет такую установку,
подписи поставщика или review кода зависимостей.

Обычный `requirements.yml` не запускает установку автоматически. Подключение
Ansible Vault и SecretRefs остаётся отдельной незавершённой частью E1.

После preview R5 добавлен внутренний offline-модуль `dependency_archive.py`.
Он ещё не подключён к helper RPC или интерфейсу и не выполняет загрузку либо
публикацию в проект. Это подготовительная часть ANS-05, а не готовый установщик.
`staged_dependency` получает точный tar/tar.gz, закреплённый lock record и
приватный каталог helper. До разбора проверяется SHA-256 архива; после
распаковки — полный `tree_digest` и точка входа роли/collection. Временное
дерево удаляется при нормальном выходе, ошибке и отказе вызывающей стороны.

Лимиты: архив 32 МиБ; файлы суммарно 100 МиБ; 10 000 файлов и 20 000 entries,
включая выведенные из путей каталоги. Все распакованные tar-байты, включая
метаданные, ограничены отдельно. До выделения памяти парсеру запрещены
запросы метаданных больше 1 МиБ и seek за лимит. Не используются
`tar.extract`/`extractall`. Symlink/hardlink, device/FIFO/sparse, дубли,
подмена родителя файлом, case-fold коллизии, traversal, непереносимые имена
и незапланированный второй архив отклоняются. Режимы нормализуются в 0600/0700;
setuid, владельцы, ACL/xattr архива не переносятся. Один wrapper-каталог
убирается только по явному `strip_components: 1`, без угадывания структуры.

Второй внутренний модуль `dependency_fetch.py` получает один закреплённый
HTTPS-артефакт: проверка сертификата и hostname обязательна, redirects не
выполняются, cookies/auth и proxy из environment не используются. Размер,
HTTP framing/encoding и SHA-256 проверяются до передачи распаковщику. URL и
ожидаемые pins фиксируются до блокирующего I/O, а не перечитываются из
изменяемого объекта после загрузки. Ошибки наружу имеют постоянный безопасный
текст, без тела ответа. Доступ к сети сам модуль не выдаёт.

Он ещё не подключён к отдельному сетевому worker. До включения нужны явный
review точного URL/доступного ему origin и жёсткий внешний process deadline:
одних socket timeouts недостаточно против медленной передачи HTTP-заголовков.
TLS-контекст из проекта не принимается; тестовый `_context` используется
только доверенным тестом с собственным CA. Отказ следовать redirects пока
требует указать конечный URL артефакта, например прямой download origin.

Доказательство: `Tasks/test_runner_dependency_archives.py`, журнал
`Tasks/automation-dependency-archive-tests.log`: 23 теста без skips в
собственном non-root контейнере без внешней сети и пользовательских данных.
Проверены поддельные PAX/GNU размеры, rollback staging, независимый snapshot
digest, настоящий локальный TLS, отказ по недоверенному CA/hostname,
redirect, подмена pins во время I/O и весь путь HTTPS → SHA → tree digest.
Содержимое роли остаётся данными и не исполняется. Остаются явное подтверждение
сети/источника, отдельный bounded worker, подтверждённая provenance в проекте,
атомарная публикация без перезаписи пользовательских файлов, обработка
сбоев/revision CAS и пользовательский workflow.

Для Ansible Vault выполнен отдельный [прототип](automation-ansible-vault.md);
защищённая выдача реальных секретов и UI ещё не подключены.

После preview r2 [reviewed requirements](automation-reviewed-requirements.md)
из ИИ-черновика могут требовать конкретный `kind`/`name`/`version` для выбранного
плейбука. Сначала проверяются все locked trees, затем наличие нужной записи и
совпадение версии. Предложение ИИ не создаёт достоверный URL/SHA, не устанавливает
зависимость и не ослабляет существующий lock.
