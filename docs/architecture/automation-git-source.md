# Ansible: импорт проекта из Git

Рабочая реализация E1, 10 ноября 2026. Это часть ANS-01, а не завершение
всего требования. Поддерживается явно выбранная ветка или тег публичного
HTTPS-репозитория через подготовленный Linux/WSL Runner. Приватная
аутентификация, обновление checkout и отправка изменений пока отсутствуют.

## Получение файлов

Клиент создаёт запись `importing` в SQLCipher до начала загрузки. Она доступна
для диагностики, но не для редактирования и запуска. Выбранный helper запускает
фиксированный `git_worker` в отдельном bubblewrap namespace. Сеть разрешена
только этому reader, без канала credentials целевых хостов. Обычные проверки
и Ansible-задания от этого не получают сетевой доступ.

Reader выполняет ограниченный bare shallow clone и читает дерево через
`ls-tree`/`cat-file`. Checkout, hooks, filters, submodules и LFS не запускаются.
Пустые HOME/config, отключённые credential helpers, SSH/agent и redirects
исключают неявное использование настроек пользователя. Аргументы передаются
отдельно, без shell. Символические ссылки и submodules отклоняются.

Для собственного удостоверяющего центра можно явно передать публичный PEM
сертификат. Клиент разбирает X.509 до передачи; приватный ключ отвергается.
CA применяется только к одной загрузке, глобальное доверие не меняется.
Сырые stderr Git и сетевые ответы не попадают в пользовательскую диагностику.

Лимиты: 10 000 файлов, 20 000 элементов, 100 МиБ содержимого; двоичные блоки
до 128 КиБ, frame до 1 МиБ. Helper ограничивает загрузку 180 секундами и
размер временной файловой системы. Это ограничения импорта, не обещание
суммарного cgroup budget или поддержки любого размера репозитория.

## Перенос и происхождение

Helper помещает `.consolecrypt-git-source.json` в снимок: URL, ref, commit,
digest CA и список исполняемых файлов. Коллизия с таким файлом в репозитории
отвергается. Обычный редактор не может изменять этот служебный файл.

Native-клиент получает дерево в новую приватную временную папку через
`files` и `read_chunk`. Он самостоятельно проверяет пути, количество, типы,
размер каждого файла, SHA-256 и итоговый tree digest. При чтении helper
проверяет каждый компонент пути без следования ссылкам. Windows сохраняет
Unix executable modes через проверенную metadata, чтобы обратная отправка
снимка не меняла его digest.

Файлы сохраняются до перевода записи в `ready`. Отмена или сбой не публикует
частичное дерево как рабочий проект. После перезапуска оставшийся `importing`
становится `interrupted`; автоматического повторного clone или запуска нет.
Закрытие окна отменяет только его import ID. Блокировка vault отзывает
активные импорты; поздний ответ не восстанавливает открытый редактор.

## Правки и запуск

Локальные изменения сохраняются с проверкой SHA прочитанного файла. Исходный
commit и digest импортированного снимка остаются в записи проекта.
Новый импорт дополнительно сохраняет отдельное исходное дерево для diff.
Это обычные локальные файлы внутри профиля, не зашифрованный переносимый
пакет: ANS-04 остаётся отдельной задачей. Суммарная квота кэша 1 ГиБ/256
деревьев, до100 МиБ на дерево, запас свободного места128 МиБ. Единственный
writer и ограниченные I/O workers не держат ключ vault во время копирования.
Копия сверяется с исходным digest до и после переноса, затем сохраняется
до публикации ready-записи. Прерванные копии учитываются квотой; автоматического
удаления пользовательских файлов или скрытого reset нет.

Перед подтверждением Git-запуска пользователь открывает «Изменения проекта».
Native сравнивает исходное дерево с текущей проверенной revision: добавление,
удаление, содержимое, тип и executable mode. Список постраничный (50 элементов);
до256 КиБ UTF-8 на сторону можно открыть рядом. Большие/двоичные файлы и
каталоги показываются как metadata-изменения. UI отображает первые32 768
символов стороны, полный текст остаётся в редакторе. Это сравнение файлов,
оно не запускает Git/hooks и не пытается вычислять квадратичный edit-distance.

Каждая страница и файл привязаны к digest подготовленного запуска. Изменение
файла, порча baseline, ошибка чтения, поздний ответ после lock/profile-change
не разрешают подтверждение. Существующие импорты без исходной копии остаются
читаемыми: для diff нужен новый импорт, а не выдуманный baseline.
Перед проверкой проекта native сверяет provenance с записью SQLCipher.

Существующий подписанный `revision_digest` включает служебную metadata и
содержимое всех файлов. Поэтому отдельное необязательное поле в подписанный
manifest v1 не вводится. Review показывает замороженный источник; история
нового задания сохраняет ту же source receipt. Указание commit не означает,
что локально изменённый проект совпадает с upstream.

## Проверки и оставшиеся ограничения

Реальные тесты используют собственный localhost TLS Git HTTP backend,
непривилегированный WSL helper, Windows automation-core и AppCore. Проверены
binary/CRLF/Unicode, modes, запрет filters и ссылок, неверный CA, отмена,
недоступность частичного импорта, ручные правки и защита provenance.
Widget-тесты отдельно проверяют отмену и поздние ответы, не заменяя native
исполнение. Результаты и точные логи перечислены в журнале
`Tasks/AUTOMATION_MONITORING_STATUS.md` основного рабочего каталога.

Последний diff-прогон: Windows core50, Linux core51 + disk2, AppCore projects9,
Flutter UI35 и чистый analyzer. Actual AppCore HTTPS import→edit→diff подтвердил
исходный текст, текущий текст, digest страниц, отказ устаревшего digest и
traversal. WSL focused suite49:46 PASS+3 optional native inventory/roundtrip
сценария не выбирались (они проверены предыдущим полным inventory-прогоном).
Native macOS/arm64 и совмещённая Git→signed execution приёмка ещё впереди.

Нативный macOS backend, Linux arm64, приватный Git, refresh с просмотром
изменений, восстановление аварийных staging-папок и управление очисткой кэша
требуют дальнейшей реализации и проверки. Эти сценарии не объявляются
готовыми на основании Windows/WSL тестов.

Совмещённая приёмка11 ноября2026: actual Git HTTPS import→локальная правка→
просмотр исходного/текущего текста→signed Ansible execution и новый retry
успешны. Изменённый marker независимо прочитан на отдельном целевом сервере,
на Runner отсутствует. История сохраняет точные commit и snapshot digest.
Подмена всей рабочей папки и повтор one-use подтверждения отклонены. Лог
`automation-git-signed-flow-integration.log`; helper86:82 PASS+4 optional native
fixture skips. Для Git создан отдельный тестовый Ubuntu24 image, прежний
образ E0 не перезаписывался. Общая macOS/arm64/mobile поставка этим не проверена.

Открытие YAML во внешнем редакторе доступно на desktop: пользователь выбирает
приложение, native сверяет SHA прочитанного файла перед OS-dispatch. Draft
сначала требует явного Save или Cancel, перечитывание с диска отдельное.
Открытие редактора не подтверждает и не запускает задание. Уже открытое
стороннее приложение работает с обычными файлами и не закрывается при lock
vault. Поздний выбор приложения после lock/profile change отклоняется.
Служебный provenance-файл через эту команду открыть для правки нельзя.
