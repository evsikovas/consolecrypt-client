# Менеджер паролей KDBX

Откройте раздел **Пароли** в боковой панели. До открытия базы доступны
**Создать KDBX**, **Открыть KDBX** и **Подключить WebDAV**, ниже — сохранённые базы.
В разделе учётных данных отдельного входа в KDBX больше нет.

После открытия сверху слева находятся папки выбранной базы, а список баз
закреплён снизу. Кнопка **+** рядом с «Базы паролей» позволяет открыть ещё одну
базу, создать новую или подключить WebDAV. В центре — список записей,
справа — увеличенная карточка выбранной записи с копированием отдельных полей и кнопкой
**Изменить**. В узком окне карточка открывается вместо списка; стрелка возвращает
к записям. Ширину папок и карточки можно менять мышью, потянув вертикальные
разделители. Ширина ограничена так, чтобы соседние панели оставались доступны.
Пароли и значения дополнительных полей в списке не показываются.

Запись можно перетащить на папку той же базы. При наведении папка подсвечивается;
перенос в другую базу этим способом не выполняется. Доступны создание групп,
новые записи, дополнительные защищённые поля и перемещение записей в корзину.
Поиск работает по названиям, логинам и URL, не просматривая значения секретов.

Каждое подтверждённое изменение автоматически записывается в зашифрованный
KDBX: создание/правка записи, новая группа, перенос и удаление. Отдельно нажимать
«Сохранить базу» не требуется. Статус показывает сохранение и его завершение.
При ошибке изменения остаются в открытой базе; доступны **Повторить сохранение**
и **Сохранить локальную копию** в меню действий базы.

Переход в терминал оставляет базы открытыми для палитры команд.
Меню **⋮ → Заблокировать базу** закрывает выбранную базу; если автоматическое
сохранение не удалось, сначала появляется подтверждение потери изменений.
Блокировка ConsoleCrypt и смена профиля закрывают все базы, прекращают WebDAV
и очищают формы.

## WebDAV и синхронизация

На стартовом экране нажмите **Подключить WebDAV** (для дополнительной базы —
**+** внизу слева) и укажите название, полный HTTPS-адрес именно файла
`.kdbx`, логин и пароль WebDAV либо отдельный токен приложения. Для редактирования
сохранённого подключения нажмите шестерёнку справа от базы. Пустое поле пароля
при редактировании сохраняет прежний пароль. Удаление подключения не удаляет
файл с WebDAV. Используется HTTP Basic поверх HTTPS; для сервисов с двухфакторной
авторизацией обычно нужен отдельный токен/пароль приложения.

Параметры подключения входят в зашифрованные настройки хранилища ConsoleCrypt.
Пароль WebDAV хранится отдельными зашифрованными учётными данными. На подключённых
к этому хранилищу устройствах с обновлённым клиентом они появляются через обычную
синхронизацию.
Сервер ConsoleCrypt не получает открытых параметров или паролей. Сам файл KDBX
хранится на выбранном WebDAV, его записи не импортируются в ConsoleCrypt.
Локальные пути запоминаются только на этом компьютере и отдельно для профиля.

Адрес должен оканчиваться именем файла **.kdbx**. Например,
`https://webdav.example/folder/Passwords.kdbx`. Один адрес сервера или папки
отклоняется сразу в форме и при открытии старого подключения, до сетевого
запроса и запроса мастер-пароля. Во время открытия доступна кнопка **Отмена**.
Таймаут подключения — 10 секунд, каждого HTTP-запроса — 20 секунд.

Открытие выполняет GET зашифрованного файла. Если GET не возвращает ETag,
клиент запрашивает свойство WebDAV `getetag` через PROPFIND с Depth: 0,
при необходимости пробует HEAD и повторяет GET с If-Match. Так полученная
версия относится именно к открываемым байтам, а не к более новому файлу.
ETag в виде простого идентификатора без кавычек нормализуется для HTTP.

Сохранение использует PUT с If-Match исходного сильного ETag. Если ответ PUT
не содержит новый ETag, клиент повторно получает и проверяет сохранённый файл;
следующее автосохранение продолжает работать. При 412 локальные изменения
остаются в открытой базе: можно сохранить копию и открыть актуальный файл.

Если надёжного ETag нет вообще или он слабый, клиент использует исключительную
блокировку WebDAV LOCK. Под блокировкой он повторно скачивает файл и сравнивает
SHA256 зашифрованных байтов с версией, открытой пользователем. Только при
совпадении выполняется PUT с токеном блокировки в If; затем отправляется UNLOCK.
Конфликт отменяет запись и тоже снимает блокировку. Если нет ни надёжного
ETag, ни допустимой блокировки, клиент не перезаписывает файл без защиты;
доступно сохранение локальной копии.

Перенаправления не выполняются: укажите конечный HTTPS-адрес, чтобы данные
авторизации не ушли другому серверу. Проверка TLS обязательна. Предел KDBX —
128 MiB; разбор метаданных ограничен 256 KiB. Вычисление отпечатка файла
выполняется в отдельном изоляте, чтобы не блокировать интерфейс.

## Windows Hello и физический ключ

Первое открытие требует мастер-пароль KDBX и, если он используется, ключевой
файл. После успешного открытия откройте меню **⋮** в панели базы и
выберите **Windows Hello / отпечаток** либо **Физический ключ FIDO2**.

Быстрое открытие включается отдельно для каждой базы на каждом компьютере.
Windows Hello показывает системную проверку отпечатком, лицом или PIN устройства.
Для физического ключа требуется FIDO2 с PRF/hmac-secret: при настройке нужны
регистрация и подтверждение, при открытии — PIN и касание. На Windows PIN
запрашивает система. Обычный ключ без PRF не подходит.

Приложение локально сохраняет только зашифрованный составной ключ KDBX. Его
отдельный криптографический конверт требует материал, который выпускает Windows
Hello либо зарегистрированный FIDO2-ключ. Конверт привязан к профилю, хранилищу,
адресу базы и способу подтверждения. Он не синхронизируется и не включается
в резервную копию ConsoleCrypt. Мастер-пароль и ключевой файл остаются запасным
способом входа. После изменения мастер-пароля в другом приложении откройте базу
паролем и заново включите быстрое открытие.

## Генератор и меню баз

Кнопка **Генератор паролей** доступна на стартовом экране раздела и в открытой
базе. В редакторе записи кнопка рядом с паролем предлагает сгенерировать новый
пароль и подставить его в поле. Это не сохраняет запись до подтверждения редактора.
Генератор доступен и при создании мастер-пароля новой базы.

Длина — от 8 до 128 символов; отдельно включаются A–Z, a–z, цифры и специальные
символы, можно исключить похожие символы. Каждая выбранная группа обязательно
присутствует. Используется криптографический генератор ОС. Копирование работает
через общий защищённый буфер с таймером из настроек ConsoleCrypt.

ПКМ по базе внизу списка открывает компактное меню: открыть/выбрать, заблокировать,
сохранить локальную копию, настроить быстрое открытие, повторить неудачное
сохранение, изменить WebDAV-подключение либо убрать базу из списка.
**Удалить из списка** требует подтверждения и оставляет файл KDBX на диске или
WebDAV. Действия относятся к базе, по которой вызвано меню, включая неактивную.

ПКМ по записи открывает меню **Открыть карточку записи**, **Переместить в другую
группу…** и **Удалить**. Для переноса выберите папку в следующем меню; текущая
папка отмечена и недоступна для повторного выбора. Перенос сохраняется сразу.
Удаление требует подтверждения и перемещает запись в корзину базы.

## Ctrl+K из терминала

1. Нажмите **Ctrl+K**, введите **пароли:** (или **passwords:**).
2. Откройте сохранённую заблокированную базу либо выберите **Открыть KDBX**.
3. После двоеточия введите название сервиса, логин или название API-поля.
4. Выберите **запись** стрелками и нажмите **Enter**. На этом шаге буфер не меняется.
5. В подменю выберите, что скопировать: пароль, логин, URL, заметки или API-поле.
   Только следующий **Enter** или щелчок по полю копирует значение.
6. **Esc** возвращает из полей к найденным записям, ещё один **Esc** — к обычным
   командам. Если уйти назад во время получения поля, копирование отменяется.

Значения секретов не показываются в результатах, не индексируются и не
передаются ИИ. Записи корзины исключены из палитры. Копирование использует общий
защищённый буфер ConsoleCrypt и срок очистки из настроек приложения; команды
в терминале при этом не выполняются.

## Сохранение и совместимость

Изменения автоматически записываются после подтверждения каждой операции.
Локальное сохранение создаёт рядом
зашифрованную копию `<имя>.kdbx.<время>.bak` и заменяет исходник через зашифрованный
временный файл. Если исходник изменился с момента открытия, перезапись запрещена.
Резервные копии удаляются пользователем. **Сохранить локальную копию** требует
нового имени и не заменяет уже существующий файл.

Поддерживаются AES-256 / ChaCha20, AES-KDF / Argon2d / Argon2id; пароль, бинарный
32-байтный, 64-символьный hex, XML v1/v2 и произвольный ключевой файл, в том числе
режим только ключевого файла. Вложения и история сохраняются при редактировании
записей; отдельный интерфейс вложений, TOTP, изменение мастер-пароля,
переименование/удаление групп и аппаратные KeePass challenge-response ключи
не реализованы. FIDO2 используется для местного быстрого открытия, без изменения
формата KDBX.

Пределы: база 128 MiB, ключевой файл 1 MiB; Argon2 до 256 MiB, 50 итераций,
16 потоков; AES-KDF до 100 млн раундов. Операция работника отменяется через
две минуты. Новая база: KDBX 4, Argon2id 64 MiB, 3 итерации, 1 поток.

Использована kdbx.dart 2.5.0, GPL-3.0. Исходники, лицензия и изменения находятся
в `client/flutter/vendor/kdbx`. Совместимость тестовых баз дополнительно
проверяется независимым читателем PyKeePass.
