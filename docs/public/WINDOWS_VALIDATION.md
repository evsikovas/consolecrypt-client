# Windows x64: проверка 0.1.4+13

Дата проверки: 28 сентября 2026 года. Собран настоящий Flutter-клиент с Rust
`cc_bridge.dll`, без `CC_MOCK`. Пакет предназначен для Windows 10/11 x64.

## Установка и данные

- Установка по умолчанию: `%LOCALAPPDATA%\Programs\ConsoleCrypt`.
- Хранилища и настройки: `%LOCALAPPDATA%\consolecrypt\ConsoleCrypt\data`.
- Системное хранилище ключей: Windows Credential Manager текущего пользователя.
- Inno Setup использует `PrivilegesRequired=lowest`; администратор не требуется.

Итоговый установщик проверен с неадминистративным токеном Windows: установка
в стандартный каталог пользователя, повторная установка, ярлык меню «Пуск»,
запуск установленного приложения и удаление завершились успешно. Установленный
EXE совпал с EXE из комплекта по SHA-256. Контрольный файл в каталоге данных
сохранился после удаления приложения, ярлык был удалён.

## Сборка

Использованы Flutter 3.47.5 / Dart 3.13.4, Rust 1.98.1 MSVC, Visual Studio
Build Tools 2026, Windows SDK 10.0.26100, Strawberry Perl 5.42.3, Python 3.11.9
и Inno Setup 6.7.3. Команда упаковки:

```powershell
.\client\scripts\build-windows.ps1 -Installer -NoCli
```

Rust/OpenSSL собираются в `target\windows-rust`, чтобы избежать слишком длинных
путей во вложенном каталоге Flutter. Комплект включает DLL Visual C++, лицензии
и папку `data`. Отдельный CLI в этот выпуск не включён.

## Проверки

- `flutter analyze`: замечаний нет.
- `flutter test`: 391 тест прошёл.
- Общие Rust-модели и протокол (`crates`): 38 тестов прошли.
- Полный Rust workspace клиента в режиме release: 523 теста прошли, 0 ошибок,
  2 явно помечены `ignored`; Cargo завершился с кодом 0. Сценарии, требующие
  отдельно настроенного Docker/SSH-сервера, не запускались против внешних хостов.
- Python-скрипты упаковки: 15 тестов прошли, 3 пропущены. Два требуют права
  создания файловых symlink в Windows, один предназначен для PowerShell на POSIX.
- `cargo fmt --check`: успешно.
- Три интеграционных сценария из `rust_core_test.dart` и
  `app_persistence_test.dart` прошли с DLL именно итогового пакета и настоящим
  Windows Credential Manager. Для запуска без повторной сборки runner использованы
  временные копии тестов с `LiveTestWidgetsFlutterBinding`, Windows как целевой
  платформой и `FRB_DART_LOAD_EXTERNAL_LIBRARY_NATIVE_LIB_DIR`, указывающим на
  полный каталог приложения. Тестовые данные и записи Credential Manager
  изолированы от пользовательских и очищены самими тестами.

Интеграционные сценарии проверяют создание профиля/хранилища, сохранение хоста
с паролем, отказ при неверной фразе, блокировку и разблокировку, повторное открытие,
экспорт/восстановление резервной копии и сохранность данных после перезапуска
интерфейса. Найденная гонка при разблокировке исправлена: событие Rust могло
закрыть экран до завершения Future, после чего код обращался к уже освобождённому
контроллеру поля пароля.

## Границы проверки

Установщик пока без подписи издателя (preview). Проверка выполнена на Windows
машине разработчика; отдельная чистая Windows без Visual Studio, Windows ARM64,
внешний SSH-хост, ИИ-провайдер и сервер синхронизации в этот прогон не входили.
Существующие пакеты macOS и Android относятся к релизу 0.1.2 и не пересобирались.

В первоначальных прогонах `sync-core/tests/profiles` и `app-core/tests/core_gaps`
могли завершаться с `STATUS_ACCESS_VIOLATION` после успешных проверок. Эти тесты
не дожидались закрытия SQLCipher на фоновых потоках перед завершением процесса
и очисткой OpenSSL. В тестах добавлены предусмотренные API вызовы `stop`,
`Storage::close` и `AppCore::shutdown`; проверки и защитные настройки сохранены.
После исправления полный параллельный прогон завершился успешно.
