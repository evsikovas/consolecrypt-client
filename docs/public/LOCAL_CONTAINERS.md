# Локальные контейнеры: Docker и WSL Containers

## Docker на этом компьютере

Откройте раздел **Docker** и выберите локальный движок. Подключения к
сохранённым SSH-хостам остаются в том же списке.

| Система | Как подключается ConsoleCrypt |
|---|---|
| macOS | Unix-сокеты и локальные Docker contexts; Docker Desktop, OrbStack, отдельные профили Colima |
| Windows | Локальные named pipes Docker Desktop и совместимых Docker contexts |
| Linux | Системный или rootless Unix-сокет, локальные Docker contexts |

При нескольких движках выбирайте нужный в списке. Текущий Docker context
показывается первым. `DOCKER_CONTEXT` имеет приоритет перед `DOCKER_HOST`.
Удалённые SSH/TCP contexts не выдаются за локальный движок: для серверов
используйте сохранённое SSH-подключение.

Поиск движков читает настройки и пути сокетов, не запускает установку Docker
или виртуальной машины. Если движок остановлен, запустите его в Docker Desktop,
OrbStack, Colima или системном менеджере служб и обновите список.

Compose использует выбранный сокет или pipe, даже если переменные окружения
Docker CLI указывают на другой context. Для Compose нужен установленный
Docker CLI с поддержкой Compose. Нативные обращения к Engine API его не требуют.

Внутренние пути томов Docker Desktop, OrbStack и Colima относятся к виртуальной
машине. ConsoleCrypt не открывает их как папки файловой системы Mac/Windows.

## WSL Containers на Windows

В разделе **Docker** нажмите **WSLc**. Этот режим использует `wslc.exe`
из установленного WSL Containers; устанавливать отдельный WSLc Desk не нужно.
Поддерживается ветка 3.x начиная с 3.0.1; разбор форматов проверен фикстурами
3.0.1.0 и 3.0.3.0. Путь к CLI можно изменить в настройках этого рабочего пространства.

Доступны функции перенесённого WSLc Desk:

- контейнеры: создание, запуск, остановка, перезапуск, логи, статистика,
  подробности, окружение, повторное создание и шаблоны;
- Compose: разбор проекта, просмотр плана и выполнение операций;
- ИИ для Compose: описание сервисов, выбор настроенного локального/API-провайдера,
  предпросмотр YAML и ручная вставка в редактор. Текущий YAML, окружение контейнеров
  и секреты автоматически не передаются. Выполнение — отдельное действие после
  проверки обычного плана; при замене заполненного редактора требуется подтверждение;
- файлы: просмотр, передача и редактирование содержимого контейнера;
- встроенный интерактивный терминал и отдельное окно терминала;
- образы и registry: поиск, загрузка, теги, импорт/экспорт архивов, авторизация;
- тома и сети: создание, просмотр, подключение и удаление;
- резервные копии томов и восстановление;
- карта связей ресурсов и выборочная очистка неиспользуемых ресурсов.

Перед удалением показывается подтверждение. Проверка подключения сама не
создаёт, не останавливает и не удаляет контейнеры; первое чтение может запустить
служебную WSL-сессию установленного WSLc.

## Общее рабочее пространство

Палитра команд, тема ConsoleCrypt и блокировка профиля продолжают работать.
Встроенный терминал использует общий защищённый буфер обмена. Вставка нескольких
строк или управляющих символов требует подтверждения; заблокированная или
заменённая сессия не получает отложенную вставку.

Скрытые переменные окружения и полный конфиг с секретами открываются через
дополнительное подтверждение доступа ConsoleCrypt. При блокировке или смене
профиля закрываются терминальные процессы и фоновые читатели этого рабочего
пространства; сами контейнеры продолжают работать.

Настройки WSLc и шаблоны сохраняются в зашифрованной локальной базе текущего
профиля. Отдельный незашифрованный файл настроек WSLc Desk не используется.
Настройки темы, автозапуска и трея остаются общими настройками ConsoleCrypt.

Сохранённые подключения к БД через конкретный локальный Docker-движок, включая
их пароли, остаются только на этом устройстве. Движок определяется по сокету
или pipe: смена имени/context не переводит подключение на другой движок.
Такие подключения не синхронизируются и не передаются в совместный доступ.
Обновление протокола или сервера синхронизации для этих данных не требуется.

## Проверка рабочей версии

Автоматические проверки используют фикстуры WSLc, изолированный тестовый pipe,
проверки профилей, шифрования, маршрутов и интерфейса. Это не означает проверки
всех изменяющих операций на всех установках Docker/WSLc. Перед выпуском нужны
нативные сборки и проверка выбранных провайдеров на соответствующих системах.
