# Базы данных / Databases

## Русский

Раздел «Базы данных» работает с PostgreSQL, MySQL/MariaDB, ClickHouse, Redis и
MongoDB. Он показывает структуру базы, даёт редактор запросов с историей,
таблицу результатов, копирование и экспорт, а также помощника ИИ. Драйверы
встроены в приложение, поэтому `psql`, `mysql`, `clickhouse-client`,
`redis-cli` и `mongosh` устанавливать не нужно.

### Подключение

1. Откройте «Базы данных» в боковой панели и нажмите «Новое подключение».
2. Укажите движок, адрес, порт, базу (для Redis — номер базы), пользователя и
   пароль. Пароль можно сохранить в хранилище или вводить при каждом открытии.
   Введённый при открытии пароль используется один раз и не сохраняется.
3. Выберите TLS: `disable`, `prefer`, `require` или `verify`. В режиме
   `verify` сертификат проверяется по имени сервера базы, даже если соединение
   идёт через SSH-туннель.
4. Выберите маршрут: напрямую, через сохранённый SSH-хост или jump-профиль
   ConsoleCrypt.
5. Для рабочей базы включите «Прод» (см. ниже).

Подключение можно импортировать из строки (`postgres://`, `mysql://`,
`clickhouse://`, `redis://`, `mongodb://`, `mongodb+srv://`) или из файла
`.pgpass`. Если файл `~/.pgpass` (или `$PGPASSFILE`) есть, он читается сразу,
иначе открывается выбор файла. Перед сохранением показывается список найденных
подключений: для каждого можно включить «Прод», выбрать маршрут и решить,
сохранять ли пароль. Строки с подстановками `*` и локальными сокетами
пропускаются.

Подключения и пароли хранятся в зашифрованном хранилище и синхронизируются
через сервер ConsoleCrypt в зашифрованном виде. Запросы идут с устройства к
базе по выбранному маршруту; сервер синхронизации их не видит.

### Режим «Прод»

Прод-подключение работает только на чтение, и защита у него в два слоя:

- **На сервере.** PostgreSQL и MySQL/MariaDB выполняют каждый запрос в
  транзакции только для чтения. ClickHouse получает `readonly=2` в каждом
  запросе. У Redis серверного переключателя нет. Для MongoDB проверяются роли
  пользователя: если у него только права на чтение, это видно в окне
  подключения.
- **В приложении.** Каждый запрос разбирается до отправки. Изменяющие команды и
  попытки снять защиту (`SET transaction_read_only`, `COPY … TO PROGRAM`,
  `INTO OUTFILE`, `FLUSHALL`, `$out`, `$merge` и подобные) не отправляются.

Временного «окна записи» у баз нет: чтобы что-то изменить в проде,
используйте отдельное непрод-подключение с другой учётной записью. Кнопка
«Проверить права» предупредит, если роль прод-подключения может изменять
данные. Для прод лучше использовать роль только для чтения: в PostgreSQL —
`SELECT` или `pg_read_all_data`, в MySQL — `SELECT`, в ClickHouse — профиль
`readonly=1`, в Redis — ACL `+@read -@write`, в MongoDB — роль `read`.

На непрод-подключении изменяющий запрос перед выполнением показывается в окне
проверки с именем подключения. Опасные запросы (`DROP`, `TRUNCATE`, `UPDATE`
или `DELETE` без `WHERE`, `FLUSHALL`, удаление коллекции) отмечены отдельно.
Команда Redis `KEYS` не выполняется никогда: вместо неё предлагается такой же
`SCAN`, который можно открыть в новой вкладке.

### Структура

Дерево загружается по мере раскрытия:

- **PostgreSQL**: схемы → таблицы, представления, материализованные
  представления, последовательности, функции и процедуры → колонки (тип,
  NULL, значение по умолчанию, первичный и внешний ключ), индексы,
  ограничения, триггеры.
- **MySQL/MariaDB**: базы → таблицы, представления, процедуры и функции →
  колонки, индексы, триггеры.
- **ClickHouse**: базы → таблицы (движок), представления, словари → колонки
  (ключ сортировки), skip-индексы и проекции.
- **Redis**: `db0`…`db15` → папки ключей по разделителю `:` → ключи с типом и
  TTL. Ключи читаются порциями через `SCAN`.
- **MongoDB**: базы → коллекции → индексы.

В меню объекта: «Первые строки», «Показать DDL» (для Redis — описание ключа,
для MongoDB — параметры коллекции и индексы), «Вставить имя». Для коллекций
MongoDB есть «Схема по выборке»: типы полей и доля документов, в которых поле
встречается.

### Редактор

- Вкладки запросов, `Cmd/Ctrl+Enter` — выполнить текущий запрос или
  выделение. Можно выполнить и весь скрипт: запросы идут по очереди и
  останавливаются на первой ошибке.
- `Cmd/Ctrl+Space` — дополнение: ключевые слова, таблицы и колонки, в том числе
  по псевдониму (`o.` после `FROM orders o`).
- `Cmd/Ctrl+Shift+F` — форматировать, `Cmd/Ctrl+/` — закомментировать,
  `Cmd/Ctrl+F` — поиск и замена, `Cmd/Ctrl+.` — отменить запрос,
  `Cmd/Ctrl+E` — EXPLAIN, `Cmd/Ctrl+H` — история, `Cmd/Ctrl+I` — ИИ.
- Переменные `{{name}}` заполняются в отдельном окне и передаются драйверу
  как параметры, а не вставляются в текст.
- EXPLAIN показывает план. `EXPLAIN ANALYZE` выполняет запрос, поэтому на
  непрод он идёт через окно проверки, а на проде недоступен.

### Результаты, копирование и экспорт

Сетка загружает по 1000 строк (лимит настраивается в подключении), остальное
подгружается кнопкой «Загрузить ещё». Значения колонок с именами вроде
`password`, `token`, `secret` скрыты, а при копировании буфер обмена
очищается автоматически.

Копировать можно ячейку, строки или весь результат в CSV, TSV, JSON, NDJSON,
Markdown или как SQL `INSERT`. Экспорт в файл заново выполняет запрос и
записывает все строки без лимита сетки, с прогрессом и отменой. Экспортируются
только запросы на чтение: изменяющий запрос для экспорта не повторяется.

### Редактирование ячеек

На непрод-подключении на компьютере можно менять ячейки результата простого
`SELECT` из одной таблицы с первичным ключом. Изменения копятся. Перед
применением показываются сгенерированные `UPDATE … WHERE <первичный ключ>`
(значения передаются параметрами), после подтверждения они выполняются одной
транзакцией. Если какое-то изменение не нашло свою строку, откатываются все.
На проде редактирование недоступно.

### История

История запросов ведётся по каждому подключению: текст, время,
длительность, число строк и ошибка. Значения параметров и данные результатов
в неё не попадают. По умолчанию история хранится только на этом устройстве в
зашифрованном виде. Её можно включить в зашифрованную синхронизацию или
отключить. Запрос из истории можно сохранить как сниппет: переменные
`{{name}}` станут переменными сниппета.

### Помощник ИИ

Помощник работает с провайдерами из «Настройки → ИИ»: локальными (Ollama,
LM Studio, встроенная модель) или внешними по API. Он умеет:

- составить запрос по описанию;
- объяснить или исправить запрос;
- оптимизировать запрос по плану EXPLAIN;
- перевести запрос в другой диалект;
- сделать из запроса сниппет с переменными;
- предложить типовые запросы к таблице;
- объяснить выбранные строки результата.

Перед каждым запросом к модели открывается окно согласия:

- **Схема** — имена таблиц и колонок с типами, без данных.
- **Выбранные строки** — только те, что вы отметили в результате.
- **Выборка строк** и **проверочный запрос** — модель может посмотреть до 20
  строк таблицы или выполнить один запрос на чтение (до 50 строк, 10 секунд).
  Запись этим путём невозможна даже на непрод.

Без согласия модель не получает ни схему, ни данные. Пароли, строки
подключения и адреса серверов не отправляются никогда. Колонки с секретами
скрываются. Для внешних провайдеров с профилем приватности Strict имена таблиц
и колонок заменяются псевдонимами, а в ответе восстанавливаются.

Ответ помощника — черновик в редакторе. Сам он ничего не выполняет: запрос
запускаете вы, с обычными проверками. Для прод-подключений черновики DDL
только показываются.

### Платформы

В этой сборке раздел доступен на macOS. Остальные платформы появятся в
выпуске 0.7.2.

## English

The Databases section works with PostgreSQL, MySQL/MariaDB, ClickHouse, Redis
and MongoDB. It covers the structure tree, a query editor with history, a
result grid, copy and export, and the AI assistant. The drivers are built into
the app; no external command-line clients are needed.

- **Connections** live in the encrypted vault and sync end-to-end encrypted.
  Queries go from the device to the database directly or through a saved SSH
  host or jump profile. TLS `verify` checks the database host name even
  through a tunnel. Import connection strings or `.pgpass`.
- **Production** connections are read-only in two layers: the server
  (read-only transactions, ClickHouse `readonly=2`) and the native query guard,
  which blocks writes and attempts to lift the protection. There is no
  temporary write window; use a separate non-production connection. "Check
  privileges" warns when a production role can write.
- **Structure**: schemas, tables, views, functions, columns with keys,
  indexes, constraints and triggers; Redis keys by `:` folders via `SCAN`;
  MongoDB collections and indexes with a sampled schema.
- **Editor**: completion of keywords, tables and columns,
  `{{variables}}` bound as parameters, formatting, EXPLAIN and cancel. The
  shortcuts are the same as in the Russian section above.
- **Results**: 1,000 rows per page, sensitive columns masked, copy as CSV, TSV,
  JSON, NDJSON, Markdown or `INSERT`, and streamed file export of read-only
  queries.
- **Cell editing** (non-production, desktop): reviewed parameterized updates
  in one transaction that rolls back unless every change hit exactly one row.
- **History**: per connection and local by default; encrypted sync or off on
  request; save as a snippet.
- **AI assistant**: compose, explain, fix, optimize, translate and
  parameterize queries. Schema, selected rows, row samples and read-only
  probes are shared only with per-request consent. Strict profiles
  pseudonymize identifiers for external providers. Drafts are never run
  automatically.
